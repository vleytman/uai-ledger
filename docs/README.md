# Универсальная AI-платформа

Согласованные доработки по запросам LogoPanel от 25.09.2026: [план реализации и критерии приёмки](LOGOPANEL_FOLLOWUP_PLAN.md).

Раздельный запуск backend по ролям и контейнерные шаблоны: [развёртывание](DEPLOYMENT.md).

Дата: 2026-09-18. Версия документации: 0.3, после обсуждения правил продукта, интерфейсов и тестового клиента.

Статус: спецификация 0.3 и локальная реализация. Результаты проверок приведены в [матрице приёмки](ACCEPTANCE_RESULTS.md), команды запуска в [LOCAL_RUN](LOCAL_RUN.md). Реальные прогоны OpenAI и Serper/Cartesia прошли; у Cartesia индивидуальная себестоимость остаётся unknown. Anthropic отложен владельцем, финансовые отчёты ожидают отдельного доступа. Решения обсуждения и технические настройки разделены в [DECISIONS](DECISIONS.md). Численные настройки не являются результатами эксплуатационных измерений.

Платформа выполняет запросы к AI и связанным платным инструментам, считает себестоимость, оценивает действия приложений, управляет кредитами и резервами, очередями, переключением провайдеров и сверкой. Отдельное тестовое приложение проверяет API/SDK до интеграции Logo Panel. Logo Panel остаётся первым планируемым продуктовым клиентом; предметная логика платформы от него не зависит.

## Принятые решения

1. AI-платформа является самостоятельным сервером с API, SDK и административным интерфейсом. Она предназначена для собственных проектов владельца; основной сценарий: отдельная установка на приложение, со своей базой, хранилищем, настройками и ключами провайдеров. Публичный SaaS не входит в первую версию.
2. Оплата, подписки, налоги, цена продажи пакетов и коммерческие скидки принадлежат отдельному платёжному сервису.
3. Кредит имеет постоянный внутренний бюджет расходов. Базовое значение первой версии: 1 кредит = 0,001 USD расчётной себестоимости по опубликованным применимым ставкам. Значение фиксируется до первого начисления и после этого не меняется для данной кредитной единицы.
4. Каждое начисление создаёт отдельный пакет. Исходный бюджет и условия пакета неизменяемы. Новая цена продажи влияет только на новые покупки.
5. Рост цены модели увеличивает расход кредитов на будущие операции, но не уменьшает остаток бюджета уже купленного пакета. Пакет гарантирует бюджет, а не число генераций.
6. Основной режим оплаты действия: предварительная оценка, согласованный максимум, резерв, списание по фактическому использованию в пределах принятой расчётной политики.
7. Себестоимость провайдера, расчёт с пользователем и внешняя оплата ведутся отдельно. Ошибка платформы не исчезает из учёта затрат, даже если пользователь ничего не платит.
8. Сервис сохраняет каждую попытку обращения к поставщику. Повтор HTTP-запроса клиента не создаёт новую платную попытку.
9. Unknown не означает zero. Неопределённый исход не разрешает автоматический повтор потенциально выполненного запроса.
10. Первая реализация использует одну кодовую базу, PostgreSQL, API-процесс, workers и scheduler. Разделение каждого модуля на микросервис не требуется.
11. Технически дефектные ответы модели и ошибки платформы оплачивает владелец сервиса. Валидный результат оплачивается, даже если он не понравился пользователю. В первой версии расчёт идёт за каждую успешно выполненную часть действия.
12. По умолчанию request имеет общий deadline 300 секунд и четыре попытки, максимум установки восемь. Длинное восстановление выключено; включённые задержки используют тот же счётчик. Refused и неизвестный исход не вызывают автоматического повтора. Подробности в EXECUTION.
13. После исчерпания восстановления затронутый маршрут блокируется до ручного включения. Задания ждут в фоне, имеют конечный deadline и допускают отмену. Отмена после отправки оплачивается по подтверждённому расходу.
14. Спорный резерв закрывается не позднее часа с момента возникновения неопределённости или проблемы выдачи. Неразрешённая часть освобождается, позднего автоматического списания нет.
15. Срок каждого пакета задаётся при начислении. Подписочные кредиты могут истекать в конце оплаченного периода без переноса остатка. Постоянные результаты хранит приложение, AI-сервис удаляет временные копии после подтверждения передачи.

## Что входит в первую версию

- Отдельные установки для приложений, клиентские аккаунты и кошельки внутри каждой установки.
- Текст, изображения, речь, поиск и зарегистрированные специализированные операции.
- Реестр подключений, моделей, возможностей, цен и маршрутов.
- Usage по запросам и попыткам, расчёт с учётом кеша, история цен.
- Кредитные пакеты, начисления, резервы, списания, освобождения, возвраты и отзыв начислений.
- Простой вызов через API/SDK без регистрации своего рецепта; рецепты оценки составных действий.
- Долговечная очередь, учёт общих лимитов поставщика, безопасный failover.
- Сверка там, где провайдер предоставляет подходящие данные; явный статус отсутствующей возможности.
- События по SSE, webhooks и административные уведомления.
- Передача файлов, подтверждение сохранения приложением и удаление временных копий без общей файловой системы.

## Что остаётся за границей

- Приём денег и автоматическое пополнение счета у поставщика.
- Подписки, тарифные страницы, налоговый и бухгалтерский учёт выручки.
- Персонажи, промпты ролей, история обсуждений и редакторы конкретного продукта.
- Произвольный пользовательский код и универсальный конструктор workflow.
- Прозрачная подмена неподдерживаемых возможностей модели.
- Гарантия ровно одного внешнего выполнения при любых сбоях сети без поддержки поставщика.
- Гарантия розничной маржи без знания условий продажи кредитов.

## Настройки, принятые для старта

Эти значения должны быть конфигурацией с историей изменений. Они не являются тарифными обещаниями.

| Настройка | Начальное значение |
|---|---|
| Кредитная единица | ai-credit-usd-v1 |
| Бюджет одного кредита | 0,001 USD |
| Истечение кредитного пакета | Явный expires_at при начислении; null означает явно бессрочный пакет |
| Возврат в уже истёкший пакет | Отдельный компенсационный пакет на 30 дней, см. DECISIONS |
| Порядок выбора пакетов | Ближайший срок истечения, затем дата начисления |
| Срок действия непринятой оценки | 15 минут |
| Общий срок запроса | 300 секунд по умолчанию; оперативный предел может запретить новую отправку |
| Попытки запроса | 4 по умолчанию, максимум 8; общий счётчик primary и fallback |
| Восстановление временной недоступности | Конечный backoff и явно заданные recovery delays в пределах общего числа попыток и deadline |
| Неизвестный исход или недоступный результат | Финансовое закрытие спорного резерва через 1 час |
| Временное хранение готового результата | Удаление после подтверждения приложения; предлагаемый предел без подтверждения 1 час |
| Режим списания | actual_usage |
| Скрытая наценка AI-сервиса | Отсутствует |
